# Negarin — WordPress + WooCommerce Theme

Fashion/abaya storefront theme with an editor-driven homepage builder,
phone+OTP-only authentication, and full RTL/Persian support.

> **Status: Phase 0–8 delivered.** Every page from the original brief is
> built, and this phase did a full **mobile-responsiveness pass** against
> real mobile screenshots (homepage, single product, login) plus a
> full re-lint of every PHP file in the theme. See **§8.8 Mobile Pass**
> for exactly what changed and why.

---

## 1. Requirements

| | |
|---|---|
| PHP | 8.3+ |
| WordPress | 6.4+ |
| WooCommerce | 8.0+ |
| Required plugin | **Advanced Custom Fields** (free, ≥ 6.1 — Flexible Content is free as of 6.1) |
| Recommended plugin | Polylang (multilingual) |
| Node | 20+ (build tooling only, not needed on the server) |

## 2. Installation

1. Zip the `negarin/` folder (or use the prebuilt ZIP) and upload via
   **Appearance → Themes → Add New → Upload Theme**.
2. Activate **Advanced Custom Fields** (free) and **WooCommerce** — the
   theme shows an admin notice if either is missing.
3. Activate the **Negarin** theme.
4. Add this to `wp-config.php` for OTP SMS delivery:
   ```php
   define( 'NEGARIN_KAVENEGAR_API_KEY', 'your-api-key' );
   define( 'NEGARIN_KAVENEGAR_OTP_TEMPLATE', 'negarin-otp' );
   ```
   (See **SMS Integration** below to use a different provider.)
5. **Settings → Reading**: set a static page as the homepage.
6. Edit that page → **Page Attributes → Template → "Page Builder (Flexible Sections)"**.
7. Scroll down to the **Sections** field and start adding blocks (see below).

## 3. Build (development)

```bash
npm install
npm run dev     # Vite dev server + HMR, writes a .vite-dev flag the theme detects
npm run build    # production build -> assets/build/, manifest.json read by PHP enqueue
```

The theme works with **zero Node.js on the production server** — you only
run `npm run build` locally/CI and deploy the compiled `assets/build/` folder.

## 5. The Homepage / Page Builder

This is the reusable section system you asked for: **every section's
layout is chosen per-instance from wp-admin**, not hardcoded per page.

Available section types (add more from `inc/services/FlexibleContent.php`
+ a matching `template-parts/sections/{name}.php` — nothing else to wire up):

| Layout | Matches design | Editable fields |
|---|---|---|
| **Hero** | full-bleed opening image | image, eyebrow, title, text, button, overlay position |
| **Image + Text** | "عبای لبخند", "عبای هستی", "عبای رخش", "عبای ایران" blocks | **image side (right/left) is a per-section toggle**, eyebrow, title, text, button, background color |
| **Image Grid** | the two/three-photos-side-by-side rows | 2 or 3 columns, each image with optional caption + link |
| **Banner** | packaging / gift-box full-width shots | single image, optional link |
| **Product Carousel** | (ready for a "shop the look" row) | pulls from a WooCommerce category or a manually curated product list |

Sections can be added, removed, and reordered by drag-and-drop in the
WordPress editor — the homepage in the Figma export maps to roughly:
`Hero → Image Grid(2) → Image+Text → Image Grid(2) → Banner → Image+Text →
Image+Text → Image Grid(3) → Image+Text → Image Grid(2) → Image+Text →
Image+Text`.

## 7. OTP Authentication

- No email/username login exists anywhere in the storefront
  (`inc/hooks/otp-guards.php` disables password auth for the `customer`
  role and swaps WooCommerce's My Account login form for the OTP form).
- **Screen** (`template-parts/components/otp-login-form.php`): a chrome-less
  split-screen — a decorative editorial photo + welcome card on one side
  (image + text editable at **Theme Options → Login Screen**), phone entry
  then code entry on the other. Reached by simply visiting **My Account**
  while logged out (`woocommerce/myaccount/my-account.php` renders it
  instead of the dashboard); the site header/footer are suppressed on this
  screen only (see the `is_account_page() && ! is_user_logged_in()` check
  in `header.php`/`footer.php`) to match the export exactly.
  "ویرایش شماره" (edit number) returns to the phone step without losing
  the resend cooldown state; "ارسال مجدد کد" respects the same
  server-side cooldown as everywhere else.
- REST endpoints: `POST /wp-json/negarin/v1/otp/{request,resend,verify}`.
- 5-digit code, 2-minute expiry, 60-second resend cooldown, 5
  requests/hour rate limit per phone number — all in
  `inc/services/OtpAuth.php`.
- A user is auto-created on first successful verification (role `customer`,
  phone stored in `negarin_phone` + `billing_phone` user meta).

### SMS Integration

The gateway is abstracted behind `Negarin\Services\Sms\SmsGatewayInterface`.
**Kavenegar** ships as the default implementation
(`inc/services/Sms/KavenegarGateway.php`, using the `lookup` OTP template
endpoint for instant delivery). To use a different provider, add your own
class implementing the same interface and swap it in:

```php
add_filter( 'negarin_sms_gateway', function () {
    return new \My\Custom\SmsGateway();
} );
```

## 8. Custom Sizing Orders ("سفارش شخصی")

Any product can opt in via a checkbox on its edit screen (**Custom Order
(Sizing)** field group). When enabled, a "سفارش با اندازه شخصی" button
appears (wire it into `woocommerce/content-single-product.php` once that
template exists) and opens a modal built from **Theme Options → Sizing
Presets** — an admin-managed list of measurement fields (دور سینه، قد عبا،
قد آستین، ...), each with:

- a dropdown of admin-defined preset ranges, **and**
- a manual-entry toggle for exact numbers,

per your answer, both input modes are available on every field. A nested
"راهنمای اندازه‌گیری" modal (static WYSIWYG + optional illustration, also
in Sizing Presets) opens on top of it.

If the shopper isn't logged in, the same modal collects name + phone.

**Storage:** exactly as you specified — measurements are attached to the
cart item and, on checkout, WooCommerce copies them to **order item meta**
(`inc/services/CustomOrder.php`), visible on the order edit screen, in
order emails, and in the customer's order history — no separate CPT.

The form submits as a normal WooCommerce add-to-cart POST (not a custom
AJAX reimplementation), so it stays compatible with every other
add-to-cart hook/plugin in the stack, validates server-side
(`woocommerce_add_to_cart_validation`), and degrades gracefully with JS
disabled.

## 8.2 Cart, Checkout & Order Received

- **Cart** (`woocommerce/cart/cart.php`): product table (right/wide column)
  + a "فاکتور شما" invoice sidebar (left/narrow column) with subtotal,
  total, a gift-shipping note, and a "تایید و ادامه" button to checkout.
  Quantities use a custom −/+ stepper
  (`template-parts/components/quantity-stepper.php`) that wraps
  WooCommerce's own quantity `<input>` — it doesn't reimplement cart math,
  it just clicks WooCommerce's native (visually hidden) "update cart"
  button for you (`assets/js/cart.js`).

- **Checkout** (`woocommerce/checkout/form-checkout.php`): a **two-step
  wizard built on top of WooCommerce's single, standard `<form
  name="checkout">`** — not a reimplementation of checkout processing.
  Step 1 (address) and step 2 (payment) are both rendered into the same
  form and toggled with Alpine `x-show`; WooCommerce's own AJAX order
  review, payment-gateway JS, and `#place_order` submit all keep working
  untouched, so **every payment gateway plugin stays compatible with zero
  extra work**. If server-side validation fails, the wizard automatically
  jumps back to step 1 (`assets/js/checkout.js`).
  - Field labels/order are customized in `inc/services/CheckoutFields.php`
    to match the export (نام/نام‌خانوادگی، استان/شهر، آدرس، **پلاک/واحد**
    — two custom fields added and saved as order meta — کدپستی).
  - "Ship to a different address" is disabled (design collects one address).
  - Payment method radios are re-styled via CSS to the bordered-card look
    in the export, without touching WooCommerce's markup/JS hooks.

- **Order Received** (`woocommerce/checkout/thankyou.php`): the "نوش تن و
  جانِ شما" success screen, with a failed-payment fallback state
  (retry-payment button) since the design only showed the success case.

## 8.3 My Account Dashboard

- **Wrapper** (`woocommerce/myaccount/my-account.php`): greeting card
  ("سلام {نام}!" + phone) and a 3-item nav (اطلاعات من / سفارش‌های من با
  نشان تعداد / خروج) on the right, endpoint content on the left. The nav
  is trimmed from WooCommerce's own `wc_get_account_menu_items()` via
  `inc/services/AccountMenu.php` — it's a filter, not a hardcoded list, so
  any endpoint another plugin registers is simply omitted unless added
  back to the allow-list there.
- **Orders** (`woocommerce/myaccount/orders.php`): product name / date /
  quantity / colored status pill ("تحویل داده شده" green, "در حال آماده
  سازی" amber, ...) / "مشاهده جزئیات" — one row per order, showing its
  first line item (fits the shop's typically single-item orders; a
  multi-item order still shows correctly, just summarized by its first item).
- **Profile** (`woocommerce/myaccount/form-edit-account.php`): نام،
  نام‌خانوادگی، a custom "نحوه آشنایی با نگارین" field (stored as user
  meta via `inc/services/AddressBook.php`), ایمیل, and a "منزل" address
  summary card with a working edit (pencil → WooCommerce's own billing
  address endpoint) and **delete** (trash → clears the billing_* fields;
  WooCommerce itself has no "delete address" concept, so this was added).

## 8.4 Blog & SEO

No screenshot existed for the blog, so — same as the shop archive — it
was designed to match the established system. Since you specifically
asked what would help SEO, here's what's implemented and why:

- **Structured data (`inc/services/Seo.php`)**: `BlogPosting` JSON-LD on
  every post (headline, dates, author, image, description) and a
  `BreadcrumbList` JSON-LD wherever breadcrumbs show — built from the
  same `negarin_get_breadcrumbs()` helper as the visible breadcrumb UI, so
  they can never drift out of sync with each other. This is the single
  highest-value SEO addition for a small store: it's what lets Google
  show breadcrumb trails and rich article cards in search results.
- **Meta description + Open Graph tags**: only output when **neither
  Yoast nor RankMath is active** (`WPSEO_VERSION` / `RankMath` class
  checks) — since the brief said RankMath/Yoast-compatible, this avoids
  ever fighting with whichever one you install. Falls back to
  auto-summarizing the content if no meta description was written.
- **Focus keyword + meta description fields** (`inc/services/BlogFields.php`,
  meta box "SEO & Related Products" on every post).
- **Related Products**: manually pick specific products, or leave it
  blank and it searches WooCommerce products by the **focus keyword**
  automatically (`BlogFields::get_related_products()`). This directly
  answers your "based on focus keyword or manual" question — both modes
  exist, manual always wins if set.
- **Table of Contents** (`inc/helpers/template-tags.php` →
  `negarin_extract_toc()`): auto-generates anchor IDs for every H2/H3 in
  the post body and renders a collapsible "فهرست مطالب" box — built from
  a single regex pass shared between the injected content and the TOC
  list, so they can't go out of sync. TOC/anchor structure like this is
  also what Google sometimes uses for sitelinks/jump-to sections in
  search results.
- **Reading time** (`negarin_reading_time()`) and **related posts** (same
  category) round out the on-page engagement signals.
- Category and date archives (`archive.php` — WordPress' own template
  hierarchy routes both to it automatically unless a more specific
  `category.php`/`date.php` is added later) both work out of the box, as
  requested.

## 8.6 Off-canvas Menu

The header was reshaped to logo-start / icon-cluster-end (account, search,
cart, hamburger) with **no separate desktop nav row** — the hamburger opens
a full-screen drill-down panel at every breakpoint
(`template-parts/header/offcanvas-menu.php`), matching the mobile-menu
export. It's driven entirely by the **Primary Menu** location in
**Appearance → Menus**: any top-level item with children automatically
becomes a "‹ drill in / back ›" sub-panel via a custom
`Negarin\Classes\OffcanvasMenuWalker` — nothing is hardcoded, so the exact
menu labels/structure from the screenshot ("خانه نگارین", "محصولات نگارین"
with its sub-list, "ارتباط با نگارین", "روایت داستان نگارین", "ورود |
ثبت‌نام") are just menu items an editor creates in wp-admin.

## 8.7 Mobile Responsiveness Pass

Checked against real mobile screenshots (homepage, single product, login).
Differences found and fixed:

- **Homepage image grids** (`template-parts/sections/image-grid.php`):
  were incorrectly collapsing to a single column on mobile; the export
  keeps them at 2 (or 3) columns at every width. Fixed.
- **Footer** (`template-parts/footer/site-footer.php`): the mobile export
  showed a centered logo, footer nav links, and a short "برای نگارین
  بنویسید" message form + social icons that didn't exist before — added,
  including a working submit handler (`inc/services/FooterMessage.php`,
  emails the site admin, with a honeypot field against spam bots).
- **Single Product gallery** (`template-parts/components/product-gallery.php`):
  desktop stacks every image full-width (as before); **mobile is now a
  swipeable one-image-at-a-time carousel with dot indicators**, matching
  the mobile export exactly — both are driven by the same image list, only
  the CSS layout changes per breakpoint.
- **Single Product action order**: the mobile export puts the "خرید
  کالای موجود / سفارش شخصی" buttons immediately after the gallery, *before*
  the title/price — desktop keeps title/price first. Implemented with
  Tailwind `order-*` utilities on the existing markup rather than
  duplicating it.
- **Login screen**: desktop is a true two-column split (image as its own
  full-height column); mobile stacks logo → input → the same decorative
  image (now shown inline, it was previously desktop-only) → button,
  matching the mobile export.
- Full re-lint of every `.php` file, plus a scripted check that every
  `get_template_part()` call in the theme resolves to a real file —
  no dangling references found.

## 10. Known Limitations (current phase)

- City (`شهر`) is a free-text field, not a province-dependent dropdown —
  a live province→city list needs a data source (e.g. an Iranian
  provinces/cities JSON) I don't have yet; happy to wire it in once you
  share or approve one.
- پلاک/واحد save to order meta but aren't yet shown in the WooCommerce
  admin order screen or order-confirmation email — quick follow-up once
  the account/order-detail screens are built (§ dashboard, next phase).
- Mini-cart drawer (slide-out panel) isn't built yet — cart count in the
  header works; the full-page cart (`/cart`) is the only way to review
  the cart for now.
- "Delete address" clears billing_* user meta directly (no confirmation
  screen beyond the JS `confirm()` dialog) since WooCommerce has no native
  address-deletion concept — acceptable for a single-address account, but
  note this if multi-address support is ever added later.

- WooCommerce shop/product/cart/checkout/my-account templates are not yet
  overridden — WooCommerce's own default templates render for now.
  Send the Figma exports for these pages next.
- Blog archive/single/search/404 templates are minimal placeholders.
- Wishlist, coupon UI polish, and mini-cart drawer animation are stubbed
  (cart count fragment works; a slide-out drawer panel is next).
- No demo content / screenshot.png yet — add once real product photography
  is available.
